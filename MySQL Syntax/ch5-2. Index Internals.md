# Chapter 5-2 — How Indexes Work Internally

> The B-tree structure behind indexes.

## 1. The B-tree

MySQL indexes are stored as a **balanced tree (B-tree)** with three node levels:

```
           [ Root node ]            ← single entry point
          /     |      \
   [Branch]  [Branch]  [Branch]     ← intermediate, route the search
    /  |       |  \      |  \
 [Leaf][Leaf]      …          ← actual sorted keys (bottom level)
```

- **Root node** — the top; every search starts here.
- **Branch (internal) nodes** — direct the search toward the right leaf.
- **Leaf nodes** — hold the sorted key values (and, for clustered indexes, the data itself).

Because the tree stays **balanced**, any row is found in roughly the same, small number of steps: search cost is **O(log n)** instead of O(n) for a full scan.

## 2. Pages

The unit of storage and I/O is a **page** (InnoDB default **16 KB**). The DBMS reads whole pages, not single rows; a B-tree node maps to a page. Fewer page reads = faster queries, which is exactly what an index buys you.

## 3. Clustered vs secondary at the leaf level

| | Leaf node contains |
| --- | --- |
| **Clustered index** | the **full data rows**, sorted by the key (the leaf level *is* the table) |
| **Secondary index** | the indexed key + the **clustered key (PK)** as a pointer |

So a secondary-index lookup often does **two** traversals: find the PK in the secondary index, then use the PK to walk the clustered index to the row.

## 4. Page split

When a new row is inserted into a full page, the page **splits** into two and the tree rebalances. Frequent random inserts cause many splits → fragmentation and write overhead. This is one reason an ever-increasing key (like `AUTO_INCREMENT`) is friendlier to a clustered index than a random key.

## Key takeaways

- Indexes are balanced B-trees: root → branch → leaf, giving O(log n) search.
- Storage/I-O happens in pages (InnoDB 16 KB).
- Clustered leaf = the data; secondary leaf = key + PK pointer (often a double lookup).
- Inserts into full pages trigger page splits — prefer sequential keys.
