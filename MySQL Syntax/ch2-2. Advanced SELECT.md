# Chapter 2-2 — A Deeper Look at `SELECT`

> Sorting, limiting, de-duplicating, and grouping results.

## 1. `ORDER BY` — sorting

```sql
SELECT mem_id, mem_name, debut_date FROM member
ORDER BY debut_date ASC;     -- ascending (default)

SELECT mem_id, mem_name, height FROM member
WHERE height >= 164
ORDER BY height DESC, debut_date ASC;   -- multi-key sort
```

- `ASC` ascending (default), `DESC` descending.
- Multiple keys: sort by the first; ties broken by the next.

## 2. `LIMIT` — capping rows

```sql
SELECT * FROM member ORDER BY debut_date LIMIT 3;       -- first 3
SELECT * FROM member ORDER BY debut_date LIMIT 3, 2;    -- skip 3, take 2
```

`LIMIT offset, count` — useful for "top N" and pagination.

## 3. `DISTINCT` — removing duplicates

```sql
SELECT DISTINCT addr FROM member;   -- each region once
```

## 4. `GROUP BY` + aggregate functions

`GROUP BY` collapses rows that share a value into one group; aggregate functions summarize each group.

| Function | Returns |
| --- | --- |
| `SUM()` | total |
| `AVG()` | average |
| `MIN()` / `MAX()` | smallest / largest |
| `COUNT()` | row count |
| `COUNT(DISTINCT col)` | distinct value count |

```sql
-- total quantity purchased per group
SELECT mem_id, SUM(amount) AS total_amount
FROM buy
GROUP BY mem_id;

-- total spend per group (price × amount)
SELECT mem_id, SUM(price * amount) AS total_spend
FROM buy
GROUP BY mem_id;
```

## 5. `HAVING` — filtering groups

`WHERE` filters **rows before** grouping; `HAVING` filters **groups after** grouping. Aggregate conditions must go in `HAVING`.

```sql
SELECT mem_id, SUM(price * amount) AS total_spend
FROM buy
GROUP BY mem_id
HAVING SUM(price * amount) > 1000     -- only big spenders
ORDER BY total_spend DESC;
```

## 6. Full clause order

SQL clauses are written — and logically evaluated — in this order:

```
SELECT   columns / aggregates
FROM     table
WHERE    row filter            (before grouping)
GROUP BY grouping columns
HAVING   group filter          (after grouping)
ORDER BY sort
LIMIT    row cap
```

## Key takeaways

- `ORDER BY` sorts; `LIMIT` caps; `DISTINCT` de-duplicates.
- `GROUP BY` + aggregates summarize per group.
- Use `WHERE` for raw rows, `HAVING` for aggregated groups — this distinction is the common exam trap.
