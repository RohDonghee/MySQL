# Chapter 4-1 — Creating Tables

> Designing a table, then building it both in the GUI and in SQL.

## 1. Design first

Before writing SQL, decide for each table: which columns exist, each column's **data type**, which column is the **primary key**, and which columns may be `NULL`.

## 2. Two ways to build

| Approach | How |
| --- | --- |
| **GUI** — MySQL Workbench | Right-click *Tables → Create Table*, fill in columns/types/keys in a form. |
| **SQL** — `CREATE TABLE` | Type the definition; reproducible and scriptable. |

The GUI generates the same `CREATE TABLE` underneath — SQL is the portable skill.

## 3. `CREATE TABLE` syntax

```sql
CREATE TABLE table_name (
    column_name  data_type  [NOT NULL | NULL]  [AUTO_INCREMENT]
                            [DEFAULT value]  [PRIMARY KEY],
    ...
);
```

Worked example:

```sql
CREATE TABLE hongong (
    id     INT          AUTO_INCREMENT PRIMARY KEY,  -- auto sequential PK
    name   VARCHAR(10)  NOT NULL,                    -- required
    age    TINYINT      DEFAULT 0,                   -- default if omitted
    addr   CHAR(2)      NULL                          -- optional
);
```

### Column option summary

| Option | Effect |
| --- | --- |
| `NOT NULL` | value required |
| `NULL` | value optional (default) |
| `DEFAULT v` | fill `v` when no value is given |
| `AUTO_INCREMENT` | auto-generate the next integer (needs to be a key) |
| `PRIMARY KEY` | unique row identifier |

## 4. Managing tables

```sql
SHOW TABLES;                       -- list tables in current database
DESC hongong;                      -- describe a table's columns
ALTER TABLE hongong ADD phone CHAR(11) NULL;   -- add a column
DROP TABLE hongong;                -- remove the table
```

## Key takeaways

- Decide columns, types, PK, and nullability **before** creating.
- GUI and `CREATE TABLE` produce the same result — prefer SQL.
- Common column options: `NOT NULL`, `DEFAULT`, `AUTO_INCREMENT`, `PRIMARY KEY`.
- Inspect with `DESC`, evolve with `ALTER TABLE`.
