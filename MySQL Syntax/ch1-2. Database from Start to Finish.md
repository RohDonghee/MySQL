# Chapter 1-2 — A Database from Start to Finish

> A first end-to-end pass through the whole workflow, done entirely in SQL.

## 1. The five-step flow

Every hands-on database task follows the same sequence:

```
1. Install DBMS   →  2. Create database  →  3. Create table
                  →  4. Insert data      →  5. Use (query) data
```

| Step | SQL |
| --- | --- |
| Create database | `CREATE DATABASE shop_db;` |
| Select database | `USE shop_db;` |
| Create table | `CREATE TABLE … ( … );` |
| Insert data | `INSERT INTO … VALUES ( … );` |
| Query data | `SELECT … FROM … WHERE … ;` |

## 2. Worked example (`shop_db`)

A minimal online shop with a members table and a products table.

```sql
CREATE DATABASE shop_db;
USE shop_db;

-- members
CREATE TABLE member (
    mem_id    CHAR(8)     NOT NULL PRIMARY KEY,  -- member ID (PK)
    mem_name  VARCHAR(10) NOT NULL,              -- name
    mem_number INT        NOT NULL,              -- number of people
    addr      CHAR(2)     NOT NULL               -- region (2 chars)
);

-- products
CREATE TABLE product (
    prod_name VARCHAR(10) NOT NULL PRIMARY KEY,
    price     INT      NOT NULL,
    amount    SMALLINT NOT NULL
);
```

```sql
INSERT INTO member VALUES ('TWC', 'TWICE', 9, 'SE');
INSERT INTO product VALUES ('wallet', 30, 2);
```

```sql
SELECT * FROM member;                 -- all rows, all columns
SELECT mem_id, mem_name FROM member;  -- chosen columns
SELECT * FROM member WHERE mem_name = 'TWICE';  -- filtered
```

## 3. GUI vs SQL

The same operations can be done two ways:

| Approach | How | When |
| --- | --- | --- |
| **GUI** (MySQL Workbench) | Point-and-click forms | Quick one-offs, learning the shape of data |
| **SQL** | Typed statements | Repeatable, scriptable, version-controllable work |

The book does Chapter 1 in the GUI as a preview, then re-does everything in SQL from Chapter 2 on — SQL is the skill that transfers.

## Key takeaways

- The lifecycle is always: create DB → create table → insert → query.
- `USE` sets the "current" database so later statements don't need a prefix.
- Anything done in the GUI can be expressed in SQL — prefer SQL for reproducibility.
