# Chapter 1-3 — Database Objects

> Beyond tables, three objects you will meet again in depth later: **index, view, stored procedure.**

## 1. Index

A data structure that lets the DBMS find rows quickly without scanning the whole table — like the index at the back of a book.

- **Benefit:** much faster `SELECT` / `WHERE` searches.
- **Cost:** extra storage, and slower `INSERT` / `UPDATE` / `DELETE` (the index must be maintained).

```sql
CREATE INDEX idx_member_name ON member (mem_name);
```

> Covered fully in **Chapter 5**.

## 2. View

A **virtual table** defined by a stored `SELECT` query. It holds no data of its own; it shows data from underlying tables.

- **Security:** expose only some columns/rows, hiding the rest.
- **Convenience:** wrap a complex query behind a simple name.

```sql
CREATE VIEW v_member AS
    SELECT mem_id, mem_name FROM member;

SELECT * FROM v_member;  -- queried like a normal table
```

> Covered fully in **Chapter 4-3**.

## 3. Stored Procedure

A named block of one or more SQL statements stored inside the database and run on demand with `CALL`. It adds programming logic (variables, conditionals, loops) to SQL.

- **Benefit:** reuse, fewer round-trips to the server, centralized logic, access control.

```sql
DELIMITER //
CREATE PROCEDURE my_proc()
BEGIN
    SELECT * FROM member;
    SELECT * FROM product;
END //
DELIMITER ;

CALL my_proc();
```
