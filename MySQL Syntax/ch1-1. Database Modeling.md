# Chapter 1-1 — Database Modeling

> The blueprint you draw **before** building a database.

## 1. Project development stages (waterfall model)

Building software follows ordered phases; a database is designed in the early ones.

| Stage | What happens |
| --- | --- |
| Analysis | Gather and define requirements ("what to build"). |
| Design | Design the system and the **database** ("how to build"). |
| Implementation | Write the actual code / SQL. |
| Testing | Verify it works and fix defects. |
| Maintenance | Operate and improve after release. |

**Key point:** Analysis and design are the most important stages — modeling errors are far cheaper to fix here than after implementation.

## 2. What database modeling is

**Database modeling** is the process of mapping real-world entities (people, products, orders) onto **tables** so they can be stored and queried. A good model decides *what tables exist, what columns each holds, and how tables relate.*

## 3. Core terminology

| Term | Meaning |
| --- | --- |
| Database | A container that holds related tables. |
| DBMS | Software that manages databases (e.g., MySQL). |
| Table | A 2-D grid of rows and columns representing one entity. |
| Row (record) | One horizontal entry — a single instance. |
| Column (field) | One vertical attribute — a property. |
| Primary key (PK) | Column that uniquely identifies each row (unique + not null). |
| Foreign key (FK) | Column that references a PK in another table (defines relationships). |
| SQL | The language used to define and manipulate data. |

## 4. Overall database structure

The containment hierarchy:

```
DBMS  →  Database  →  Table  →  Row / Column
```

One DBMS holds many databases; one database holds many tables; one table holds many rows, each described by the same columns.

## 5. Modeling tool — MySQL Workbench

The book uses **MySQL Workbench** to model visually:

- **EER diagram** — draw tables and their relationships graphically.
- **Forward engineering** — generate SQL (`CREATE TABLE …`) from the diagram.
- **Reverse engineering** — generate a diagram from an existing database.

## Key takeaways

- Design before you implement: modeling is the blueprint.
- A model = tables + columns + relationships (PK/FK).
- Workbench lets you move between diagram and SQL in both directions.
