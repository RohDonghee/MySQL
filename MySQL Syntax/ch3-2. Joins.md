# Chapter 3-2 — Joins

> Combining rows from two (or more) tables into one result.

## 1. Inner join

Returns only rows that **match** in both tables (on a join condition, usually FK = PK).

```sql
SELECT b.num, m.mem_name, b.prod_name, b.price
FROM buy AS b
    INNER JOIN member AS m
    ON b.mem_id = m.mem_id;          -- only members who actually bought
```

- `ON` states the matching condition.
- Table aliases (`b`, `m`) keep references short and unambiguous.

### Removing duplicate output

A member who bought many times appears many times. Collapse to one row per member with `DISTINCT` (or `GROUP BY`):

```sql
SELECT DISTINCT m.mem_id, m.mem_name, m.addr
FROM buy AS b INNER JOIN member AS m ON b.mem_id = m.mem_id;
```

## 2. Outer join

Keeps **unmatched** rows from one side too, filling the other side with `NULL`.

| Type | Keeps all rows from |
| --- | --- |
| `LEFT OUTER JOIN` | the left table |
| `RIGHT OUTER JOIN` | the right table |
| `FULL OUTER JOIN` | both (not native in MySQL) |

```sql
-- every member, even those who never bought anything
SELECT m.mem_id, m.mem_name, b.prod_name
FROM member AS m
    LEFT OUTER JOIN buy AS b
    ON m.mem_id = b.mem_id
ORDER BY m.mem_id;
```

> MySQL has no `FULL OUTER JOIN`; emulate it with `LEFT JOIN UNION RIGHT JOIN`.

## 3. Cross join

Every row of A paired with every row of B — the **Cartesian product** (rows = A × B). No `ON` clause.

```sql
SELECT * FROM member CROSS JOIN buy;   -- usually only for generating test data
```

## 4. Self join

A table joined **to itself**, using two aliases — typical for hierarchies (employee → manager).

```sql
SELECT e.emp AS staff, m.emp AS manager
FROM emp_table AS e
    INNER JOIN emp_table AS m
    ON e.manager_id = m.emp_id;
```

## Key takeaways

| Join | Result |
| --- | --- |
| Inner | matching rows only |
| Left / Right outer | all rows from one side + matches (`NULL` for the rest) |
| Cross | all combinations (A × B) |
| Self | a table joined to itself via aliases |

- Always state a join condition in `ON` (except cross join).
- Use `DISTINCT`/`GROUP BY` when a one-to-many join multiplies rows.
