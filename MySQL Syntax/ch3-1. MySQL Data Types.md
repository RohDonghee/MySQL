# Chapter 3-1 — MySQL Data Types

> Choosing the right type, using variables, and converting between types.

## 1. Numeric types

### Integers (signed ranges shown; `UNSIGNED` doubles the positive range)

| Type | Bytes | Signed range |
| --- | --- | --- |
| `TINYINT` | 1 | −128 … 127 |
| `SMALLINT` | 2 | −32,768 … 32,767 |
| `MEDIUMINT` | 3 | ≈ −8.3M … 8.3M |
| `INT` | 4 | ≈ −2.1B … 2.1B |
| `BIGINT` | 8 | ≈ −9.2×10¹⁸ … 9.2×10¹⁸ |

### Real numbers

| Type | Use |
| --- | --- |
| `DECIMAL(m, d)` | **exact** fixed-point — money, anything that must not round |
| `FLOAT` / `DOUBLE` | **approximate** floating-point — scientific/measurement data |

> Rule of thumb: use the smallest integer type that fits, and `DECIMAL` (never `FLOAT`) for currency.

## 2. String types

| Type | Use |
| --- | --- |
| `CHAR(n)` | **fixed** length; padded; fast for short, uniform values (codes, IDs) |
| `VARCHAR(n)` | **variable** length; stores only what's used (+ length prefix) |
| `TEXT`, `LONGTEXT` | large text (articles, descriptions) |
| `BLOB`, `LONGBLOB` | binary data (images, files) |
| `ENUM('a','b',…)` | one value from a fixed list |
| `SET('a','b',…)` | zero or more values from a fixed list |

## 3. Date & time types

| Type | Format / meaning |
| --- | --- |
| `DATE` | `'YYYY-MM-DD'` |
| `TIME` | `'HH:MM:SS'` |
| `DATETIME` | date + time |
| `TIMESTAMP` | date + time, timezone-aware, auto-updatable |
| `YEAR` | year only |

## 4. Variables

User-defined session variables hold values across statements in a connection.

```sql
SET @my_var = 5;
SELECT @my_var;

SET @count = 3;
SELECT mem_name, height FROM member ORDER BY height LIMIT 3;   -- LIMIT needs a literal/prepared value, not @count directly
```

> A user variable lives for the session and starts with `@`.

## 5. Type conversion

### Explicit — `CAST()` / `CONVERT()`

```sql
SELECT CAST('2022-12-25' AS DATE);
SELECT CONVERT(AVG(amount), SIGNED) AS avg_amount FROM buy;  -- round-ish to integer
```

### Implicit

MySQL silently converts in mixed expressions (e.g., `'100' + 5` → `105`). Convenient but a source of subtle bugs — prefer explicit casts when types differ.

## Key takeaways

- Pick the **smallest** numeric type that fits; `DECIMAL` for money.
- `CHAR` for short fixed codes, `VARCHAR` for variable text.
- User variables (`@x`) persist for the connection.
- Use `CAST`/`CONVERT` for explicit conversion; be wary of implicit conversion.
