# Chapter 5-3 — Using Indexes in Practice

> Creating, removing, and (crucially) knowing when indexes help or get ignored.

## 1. Creating and removing

```sql
-- secondary index
CREATE INDEX idx_member_name ON member (mem_name);

-- unique secondary index (also enforces uniqueness)
CREATE UNIQUE INDEX idx_member_phone ON member (phone1, phone2);

-- via ALTER TABLE
ALTER TABLE member ADD INDEX idx_addr (addr);

-- remove
DROP INDEX idx_member_name ON member;
```

Inspect and refresh statistics:

```sql
SHOW INDEX FROM member;      -- list indexes on a table
ANALYZE TABLE member;        -- recompute the optimizer's statistics
```

## 2. When an index is **not** used

Creating an index is no guarantee the optimizer uses it. Common reasons it gets skipped:

| Situation | Why the index is bypassed |
| --- | --- |
| A function/operation wraps the column: `WHERE SUBSTRING(mem_name,1,1)='B'` | The index is on `mem_name`, not on the function result. |
| Leading wildcard: `WHERE mem_name LIKE '%Pink'` | Can't seek into a sorted tree when the start is unknown. |
| Low selectivity (few distinct values, e.g., a gender flag) | A full scan is cheaper than many index lookups. |
| Type mismatch: comparing a string column to a number | Forces an implicit conversion that disables the index. |
| Returning most of the table | The index would add work, so a scan wins. |

Check what the optimizer actually does:

```sql
EXPLAIN SELECT * FROM member WHERE mem_name = 'BlackPink';
```

## 3. Guidelines for effective indexing

- Index columns frequently used in `WHERE`, `JOIN`, and `ORDER BY`.
- Prefer **high-cardinality** columns (many distinct values).
- Don't over-index: every index slows writes and consumes space.
- Keep the comparison on the **bare column** (no functions, matching types).
- Drop indexes that the optimizer never chooses.

## Key takeaways

- Manage indexes with `CREATE/DROP INDEX` (or `ALTER TABLE`), inspect with `SHOW INDEX`.
- An index can be silently ignored — functions on the column, leading `%`, low selectivity, and type mismatches are the classic culprits.
- Use `EXPLAIN` to verify; index selectively, favoring high-cardinality `WHERE`/`JOIN` columns.
