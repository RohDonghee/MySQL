# Chapter 4-3 — Views

> A virtual table defined by a query.

## 1. Concept

A **view** is a stored `SELECT` that you query like a table. It stores **no data** of its own; each time you query it, the underlying `SELECT` runs against the real (base) tables.

```sql
CREATE VIEW v_member AS
    SELECT mem_id, mem_name, addr
    FROM member;

SELECT * FROM v_member WHERE addr = 'SE';   -- used exactly like a table
```

## 2. Why use views

| Purpose | How a view helps |
| --- | --- |
| **Security** | Expose only chosen columns/rows; hide sensitive ones (e.g., phone numbers). |
| **Convenience** | Wrap a complex multi-table join behind one simple name. |
| **Consistency** | Everyone queries the same agreed definition. |

```sql
CREATE VIEW v_buy_member AS
    SELECT b.num, m.mem_name, b.prod_name, b.price * b.amount AS total
    FROM buy AS b INNER JOIN member AS m ON b.mem_id = m.mem_id;
```

## 3. Updatable views and their limits

A simple view can be updated, and the change flows to the base table:

```sql
UPDATE v_member SET addr = 'GG' WHERE mem_id = 'BLK';
```

A view is **not** updatable if it uses aggregates (`SUM`, `GROUP BY`), `DISTINCT`, `UNION`, certain joins, or derived columns (like `price * amount` above).

`WITH CHECK OPTION` rejects updates/inserts that would fall outside the view's `WHERE`:

```sql
CREATE VIEW v_seoul AS
    SELECT * FROM member WHERE addr = 'SE'
    WITH CHECK OPTION;     -- can't insert a non-Seoul member through this view
```

## 4. Managing views

```sql
ALTER VIEW  v_member AS SELECT mem_id, mem_name FROM member;  -- redefine
DROP  VIEW  v_member;                                          -- remove
SHOW CREATE VIEW v_member;                                     -- see definition
```

## Key takeaways

- A view is a named, reusable `SELECT` — virtual, holding no data.
- Main benefits: security (hide columns) and convenience (simplify complex queries).
- Simple views are updatable; aggregated/derived ones are read-only.
- `WITH CHECK OPTION` enforces the view's filter on writes.
