# Chapter 6-2 — Stored Functions and Cursors

> A routine that returns a value, and a tool for row-by-row processing.

## 1. Stored function

A **stored function** takes inputs and **returns a single value**, so it can be used inside a `SELECT` (unlike a procedure).

```sql
SET GLOBAL log_bin_trust_function_creators = 1;   -- allow function creation

DELIMITER //
CREATE FUNCTION sum_func(a INT, b INT)
    RETURNS INT
    DETERMINISTIC                 -- same input → same output
BEGIN
    RETURN a + b;
END //
DELIMITER ;

SELECT sum_func(100, 200);        -- 300, usable inline
```

### Procedure vs function

| | Stored procedure | Stored function |
| --- | --- | --- |
| Called by | `CALL` | inside an expression (`SELECT f(...)`) |
| Returns | zero or many result sets via `OUT` | exactly one value via `RETURN` |
| Can run `SELECT` to client | yes | no (computes and returns) |

## 2. Cursor

A **cursor** processes a query result **one row at a time** — useful when set-based SQL can't express the logic.

Workflow: `DECLARE` → `OPEN` → `FETCH` (loop) → `CLOSE`. A `NOT FOUND` handler detects the end.

```sql
DELIMITER //
CREATE PROCEDURE cursor_proc()
BEGIN
    DECLARE done INT DEFAULT 0;
    DECLARE h INT;
    DECLARE total INT DEFAULT 0;
    DECLARE cnt INT DEFAULT 0;

    DECLARE mem_cursor CURSOR FOR SELECT height FROM member;     -- 1. declare
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;        -- end flag

    OPEN mem_cursor;                                             -- 2. open
    read_loop: LOOP
        FETCH mem_cursor INTO h;                                 -- 3. fetch a row
        IF done = 1 THEN LEAVE read_loop; END IF;
        SET total = total + h;
        SET cnt = cnt + 1;
    END LOOP;
    CLOSE mem_cursor;                                            -- 4. close

    SELECT total / cnt AS avg_height;                            -- average height
END //
DELIMITER ;
```

> Cursors are flexible but slower than equivalent set-based SQL (here, `SELECT AVG(height) FROM member` would be simpler). Reach for a cursor only when per-row procedural logic is genuinely needed.

## Key takeaways

- A **function** returns one value and is usable inside `SELECT`; a **procedure** is invoked by `CALL`.
- Mark deterministic functions `DETERMINISTIC`; enable `log_bin_trust_function_creators` to create them.
- A **cursor** walks a result set row by row: `DECLARE → OPEN → FETCH (loop) → CLOSE`, with a `NOT FOUND` handler.
- Prefer set-based SQL; use cursors only when necessary.
